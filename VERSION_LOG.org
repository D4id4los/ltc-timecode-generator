#+TITLE: Version History for LTC Timecode Generator


* Unreleased — WP-2 audio-core restructuring

Implementation of work package WP-2 from the code-quality report
(`reports/code-quality-2026-10-02.md`, plan in
`reports/wp2-audio-core-restructuring-plan.md`): `lib.rs` becomes a
thin front door, the chunked decoder's merge logic and the scheduler's
watchdog state machine become directly unit-testable, the decoder's
strategy ladder and quality analyzer are decomposed into pure units,
backend selection becomes a trait, and the dead API surface is gone —
all behavior-preserving except where noted.

List of Changes:
- `lib.rs` split (PR-1): the 1 761-line god-module is now a ~70-line
  front door; shared types moved to `types.rs`, the byte-level WAV
  reader to `wav_chunk_reader.rs` (with `read_raw_bytes` /
  `decode_le_int_sample` deduplicating the per-reader byte work), and
  the chunked decode to `chunked_decode.rs`. The chunk-boundary loop
  exists once as `plan_chunk_boundaries`; `count_chunks` is
  `plan(..).len()` by construction. Two intentional prediction fixes:
  `count_chunks` no longer short-circuits to 1 in the
  `(chunk_mono, chunk_mono+overlap]` window (gui-engine progress
  totals were ±1 off the real decode there), and the degenerate
  `bytes_per_mono == 0` fallback unifies on 1 chunk.
- `trait LtcDecoder` (PR-2): backend selection collapses into
  `decoder.rs::decoder_for(use_libltc)` — the single `if use_libltc`
  in the crate; `decode_one_chunk`/`decode_ltc_with_decoder` delegate.
  The byte-identical `error_result` clone in the libltc decoder is
  deleted in favour of `LtcDetectionResult::error`.
- `decode_ltc_chunked` decomposition (PR-3): CC 77 → a ~70-line
  orchestrator over `ChunkPlan`, `run_sequential`/`run_parallel`
  (taking `&dyn LtcDecoder`, mockable), and `merge_results` (offset/
  dedup/reindex/confidence/status). Twelve new synthetic unit tests
  including MockDecoder sequential/parallel parity, pre-cancelled slot
  filling, and worker-bail collection.
- `list_audio_devices` (PR-4): one `AudioDeviceInfo` construction site
  (`from_summary`), one config-aggregation loop (`DeviceConfigSummary`),
  and a shared `probe_device` path for the default device and the
  enumeration loop; the duplicated second walk of
  `supported_output_configs` is gone.
- Scheduler reliability (PR-5): the callback-stall recovery state
  machine is extracted as a pure `CallbackWatchdog` (500 ms stall /
  3 attempts / 10 s sliding window / 100 ms backoff) tested on a
  virtual clock — recovery ladder, strict-`>` stall confirmation,
  resume reset, sliding-window restart, byte-exact reason string —
  plus a device-free `push_frame` helper pinning the
  `FramesDropped`-every-100 cadence. `ltc_scheduler_thread` is
  delegation + glue.
- Decoder strategy ladder (PR-6a): the 3x compare-ZC-vs-detailed
  epilogue is `prefer_zc_or_detailed`; the sliding-window loop is
  `scan_windows` returning `HighConf`/`Best`/`NoCandidate`; per-attempt
  scoring is `score_candidate`; all four `ScoredResult` construction
  sites funnel through `from_frame_starts` (single home of the
  `(phase + start·spb)/sample_rate` formula) with `canceled()` for the
  zeroed cancel stubs; four inline cancel checks become `cancelled()`.
  The real-world fixture decode output is byte-identical before/after.
- `compute_ltc_quality` (PR-6b): the ~250-line CC-48 function becomes
  a ~45-line orchestrator over pure sub-analyzers (`split_segments`,
  `analyze_drift`, `analyze_gaps`, `analyze_glitches`,
  `missing_in_span`, `quality_score`, `quality_summary`) — the scoring
  formula is now directly unit-tested. No threshold or formula changes.
- API pruning (PR-7): deleted `quick_check_ltc`,
  `is_transient_audio_error`, and the never-writable
  `OVERRIDE_SYNC_TOLERANCE` hook (the sync-word path now uses
  `SYNC_MATCH_TOLERANCE` directly, removing the inconsistent mix);
  `apply_coherent_first_timecode`, `decode_ltc_samples`,
  `decode_ltc_samples_libltc` demoted to `pub(crate)`; gui-engine's
  re-export block drops the dead names. The valid/invalid round-trip
  coverage formerly pinned by `quick_check_ltc` is retargeted onto
  `decode_ltc_from_wav`.

Verification: 390 audio-core tests (352 before, 46 new, 10 removed
with their API), full workspace suite green, clippy 0 warnings, both
GUIs compile untouched, `nextest --profile ci` green on the touched
areas, `--list-devices` and `--headless` smoke runs OK, and the
real-world 20 s fixture decode output is byte-identical across the
decoder refactors.

* Unreleased — WP-1 engine decomposition (`gui-engine`)

Implementation of work package WP-1 from the code-quality report
(`reports/code-quality-2026-10-02.md`, plan in
`reports/wp1-engine-decomposition-plan.md`): decompose the engine
god-module so `engine_main_with_probe` is a readable tick loop, make
job-event dispatch genuinely exhaustive, and remove the dead plumbing
— all behavior-preserving except where noted.

List of Changes:
- `EngineLoopState` (`gui-engine/src/engine.rs`): the twelve
  loop-carried mutable locals (snapshot, tick clock, recovery
  attempts, clap-log counter, device bookkeeping, auto-apply latches,
  deferred recording selection, publish gate, command ack counter)
  are absorbed into one struct; `process_command`,
  `handle_event`, `ensure_audio_init`, `try_init_device` and
  `attempt_recovery` take it instead of separate `&mut` arguments.
  The `#[allow(clippy::too_many_arguments)]` is gone.
- Job-event dispatch: the 330-line wildcard-tailed match is replaced
  by `handle_job_event`, which matches exhaustively on `JobKind` (a
  new kind without a handler is now a compile error) and routes to
  named per-kind handlers (`on_conversion_finished`,
  `on_ltc_decode_finished`, ...).  Payload/kind mismatches are logged,
  never silently dropped.  `JobFinal::Conversion` is now consumed: a
  successful conversion publishes "Conversion completed — video
  encoder: <enc>" to the status line, the information the encoder
  fallback machinery produced but the engine previously discarded.
- Single command dispatch site: the drain loop's inline arms moved
  into `process_command` (via `cmd_select_folder`,
  `cmd_start_conversion`, `cmd_probe_file_durations`,
  `cmd_probe_video`, `handle_converter_command`), which now owns the
  full `GuiCommand` match.  All five vestigial arms are gone,
  including the `unreachable!()` on the `ProbeVideo` arm.  Heavy
  decode arms extracted as `cmd_decode_ltc_video_group`,
  `cmd_parse_ltc_video`, `cmd_parse_ltc_wav_file`, with the probe
  validation pulled out as the unit-tested
  `validate_stream_channel_selection`.
- Converter setters: fourteen "assign one field" arms collapsed into
  `apply_simple_converter_setting` (table-tested); the four arms with
  real side effects keep dedicated handling.
- `JobStatus::running(msg)` constructor replaces four copy-pasted
  Running `JobStatus` literals.
- Publish gate: the structural `PartialEq` compare against the
  last-published snapshot now happens *before* the clone, so idle
  40 ms ticks no longer deep-clone the entire snapshot; regression
  pinned by `test_idle_engine_does_not_republish_snapshot`
  (Arc-pointer stability across idle ticks).
- Shared decode pipeline: new `gui-engine/src/decode.rs` hosts
  `decode_video_channel` / `decode_video_file`, the collision-proof
  temp-WAV naming, and the decode progress bridge.  The CLI
  (`cli.rs::run_decode_video`) and the GUI decode commands share one
  implementation instead of two ~100-line near-copies; the CLI video
  decode additionally gains the engine's chunked-decode path (the old
  `--single-pass` video shortcut is subsumed by the chunk-size
  heuristic).  WAV-mode `--decode` is unchanged.
- Offload: per-device copy-plan aggregation moved out of the engine's
  `StartOffload` arm into `offload::build_copy_plan` returning a
  typed `Result<OffloadCopyPlan, OffloadPlanError>`; display strings
  stay in the engine.  The clip-probe worker closure became
  `clip_probe::probe_clip_set`, making the
  `DEVICE_NAME_PROBE_SAMPLE` camera-probe cap unit-testable.
- Dead plumbing: `ActiveJob._started` deleted; `TrackerInner.log` is
  no longer dead — `ProgressTracker::push_log()` (4 KiB capped) is
  implemented and conversion step failures are recorded into it, so
  `JobStatus.log` / `JobOutcome` carry failure context.
- Docs: AGENTS.md synced with the new dispatch/handler structure, the
  `EngineLoopState` loop, `push_log()`, and the new `decode.rs` /
  `clip_probe.rs` modules.

* Unreleased — WP-0 correctness bundle (five verified defects fixed)

Landing of the five small correctness fixes from the code-quality
report's WP-0 work package (`reports/code-quality-2026-10-02.md`),
each developed with the project TDD loop (failing test first).

List of Changes:
- WAV fmt-scan endianness (`gui-engine/src/tagger.rs`): the bext
  tagger's fmt-chunk scanner read RIFF chunk sizes big-endian, so any
  WAV with a chunk preceding `fmt ` (LIST/JUNK from recorders) failed
  with "no fmt chunk found"; it also read the sample rate from the
  wrong fmt payload offset (format tag + channels instead of the rate
  bytes).  Consolidated on a single little-endian, padding-aware
  scanner `converter::read_wav_sample_rate_from_file`; the path-based
  `read_wav_sample_rate` now delegates to it instead of assuming
  `fmt ` is the first chunk.
- MP4 `tmcd` `stco` patch (`gui-engine/src/tagger.rs`): the native
  in-place MP4 timecode tagger shipped the tmcd track's `stco` chunk
  offset as 0 (comments promised a write-time patch that never
  existed), so spec-strict tools resolving the timecode sample read
  garbage.  The offset is now patched to the deterministic appended
  mdat payload position before the new moov is written, verified by
  an end-to-end ffmpeg+ffprobe round-trip fixture test.
- Cross-decoder confidence contract (`audio-core`): the libltc
  decoder stored `avg_confidence` as a 0–100 percentage while the
  builtin decoder used a 0.0–1.0 fraction, and libltc classified
  status as "any valid frames" (never `LowConfidence`) — libltc
  results displayed 100× too high and marginal recordings were
  classified differently per backend.  Both decoders now publish the
  same 0.0–1.0 fraction with shared `CONFIDENCE_SUCCESS_THRESHOLD` /
  `CONFIDENCE_LOW_THRESHOLD` constants; a contract test runs both
  decoders over the real-world fixture.
- Video-extension registry (`gui-engine/src/media_ext.rs`): the
  video-extension list had drifted across five sites (ffprobe,
  device_name, offload, converter/formats, tagger) — an `.m4v` file
  was ingested by offload but rejected by `path_is_video()`.  A new
  single-source registry (`VIDEO_EXTENSIONS`, `AUDIO_EXTENSIONS`,
  `is_video`/`is_audio`, `container_for_input`) now backs all
  classification and stream-copy container mapping; the duplicated
  lists are deleted.
- Subprocess hygiene (`offload.rs`, `hw_device.rs`): `udisks_mount`
  (the only production `Command::new` outside `subprocess.rs`) now
  spawns via `no_window_command` + `run_output_with_timeout` under a
  15 s timeout instead of hanging the card scan; the VAAPI/Vulkan
  hardware probes no longer call `.status()` unbounded — both run
  under a 10 s timeout, with injectable-runner seams and unit tests
  for each.

* Unreleased — unified shadow-state interaction architecture

Rework of how the GUIs communicate with the engine around interactive
widgets, following established immediate-mode-UI patterns (local shadow
state, controlled synchronisation, and an exact echo acknowledgement)
to eliminate the class of races where a widget's freshly edited value
was overwritten by a stale engine snapshot.

List of Changes:
- Engine acknowledgement counter: `AppStateSnapshot.applied_command_seq`
  is bumped by the engine once per command drained from the command
  channel and published with the tick, so a GUI can confirm exactly
  when a sent command landed (the previous mechanisms relied on value
  echo or fixed timeouts).  Idempotent writes now publish too — the
  counter forces the structural-PartialEq publish gate open.
- `gui-engine::edit_state::EditState<T>`: a GUI-framework-agnostic
  shadow-state machine (shadow value, pending send with assigned ack
  sequence, focus gate, ack confirmation, 2 s timeout fallback)
  shared by both frontends; unit-tested in-module.
- ltc-gui: every interactive widget — text fields (roll, offload
  parent/device names, converter naming templates, output folder),
  checkboxes, sliders, and all selector combos/buttons — now renders
  from a typed `EditState` shadow (`shadows.rs`) through `bound.rs`
  wrapper functions instead of re-seeding from the snapshot each
  frame.  All commands flow through a sequence-assigning sink, and
  fast repaints run while commands await their ack, so engine echoes
  appear on the next frame instead of after the idle repaint
  interval.
- ltc-gui: the two previous ad-hoc mechanisms were removed —
  `TextFieldEdit` (superseded by the generalised `EditState`) and the
  converter three-way merge/diff machinery (`local_settings`,
  `prev_engine_settings`, `merge_converter_settings`,
  `diff_converter_commands`, `reconcile_converter_settings`, the
  per-frame GUI-side `apply_available_defaults` and
  `sync_channel_map_from_probe` rewrites).  Engine-side side-effects
  (capability repair, decode auto-apply, probe channel-map resize,
  recording-selection resets) now propagate through shadow sync.
- Offload device-folder renaming is addressed by mount path
  (`OffloadCommand::SetDeviceNameByMount`) instead of the volatile
  card-list index, so a rescan during an edit can no longer retarget
  the wrong card; per-file selection checkboxes are shadow-backed.
- ltc-slint bugfixes: the converter focus gate was dead code (an
  instantiation-site property override replaced the internal focus
  aggregation with a never-written property — the gate now aggregates
  `changed has-focus` from each editable input and is two-way linked
  to the window); the ROLL TextInput lost every keystroke (the
  callback re-read the stale window property — it now carries the new
  value through a two-way binding and its poll push is focus-gated);
  the converter prefix/suffix inputs silently detached from engine
  updates after the first keystroke (one-way bindings — now two-way).

* Unreleased — state audit and cleanup

A full audit of the published application state
(`gui-engine::state::AppStateSnapshot`) — necessity, grouping, and
type quality — followed by a three-phase cleanup.  No user-visible
behaviour changes except where noted.

List of Changes:
- Dead state removed: `generation` (bumped every tick, never read),
  `wake_lock_active` (could never be true; its status chip is gone
  from both GUIs), `ltc_decode_is_video` (write-only), the
  "Trim to first LTC frame" toggle (a no-op — the pipeline supported
  trimming but the engine always passed zero offsets; embedding the
  start timecode from LTC remains the sync mechanism), the decorative
  naming-pattern selector in the Slint converter (the engine always
  scans with all patterns; its display branches now key off each
  group's actual recording type), plus published-but-unread
  `output_preview`/`encoder_chain_desc`, `system_time` (the egui GUI
  now formats its own clock, as Slint already did), and several
  set-only fields.
- Type upgrades: LTC/beep channel routing is a `ChannelSel` enum
  instead of `"left"/"right"/"both"` strings end-to-end (CLI,
  engine, audio-core); FPS is stored only as an index with `fps()` /
  `drop_frame()` accessors replacing four lockstep-maintained fields;
  the three parallel group-decode vectors collapse into a single
  `Vec<ClipDecodeState>`; `JobStatus` is now a `ProgressSnapshot`
  plus an error; `ClapLogItem.id` is a `u64`;
  `LtcQualityReport.grade` is a `QualityGrade` enum.
- Regrouping: the ten loose LTC-decode fields move into
  `AppStateSnapshot.decode` and the eight clapper/animation fields
  into `AppStateSnapshot.clapper`; device selection is by stable
  device id instead of an index into the (volatile) device list, so
  re-scans can no longer silently repoint the selection; the egui
  GUI dropped its duplicate copies of the LTC track index and the
  selected converter folder.
- All workspace clippy warnings fixed (the codebase is now
  warning-free under the workspace lint configuration).

* v0.4.7

Main features are a hardened, more responsive card-offload workflow —
live per-drive scan status, a non-blocking Start button, fixed
multi-file progress/speed reporting, an end to the endless card-scan
hang on FS100 (AVCHD) cards, and per-card scroll isolation — plus a
converter fix that stops the wrong track being dropped as LTC.

List of Changes:
- Offloading:
  - Fix progress/speed reporting for multi-file copies: the bar froze
    during files 2..N with speed reading 0 MB/s, then jumped by a whole
    file's share on completion (and could clamp at 100% early).
    Per-file deltas are now reported correctly; per-device byte
    counters use AtomicU64 so cards over 4 GiB no longer wrap on
    32-bit builds; the speed EMA no longer collapses to 0 MB/s during
    fsync/verify pauses between files.
  - Live scan status: the static "Scanning…" indicator is replaced by
    per-drive messages (e.g. "Scanning drive EOS_DIGITAL
    (/run/media/…)…"), covering the Linux auto-mount phase too, shown
    in the Offload tab and status bar of both GUIs.
  - Start Offload is non-blocking: copy plans are built from the sizes
    already collected during the card scan (zero I/O) instead of
    stat'ing every file on the card on the engine thread — the
    Start→Cancel switch is instant and the engine no longer stalls;
    ltc-gui also repaints continuously while an offload is pending or
    running (fixing the 1 Hz progress bar).
  - Fix endless card-scan hang on FS100 (AVCHD) cards: device-name
    resolution read the head+tail (8 MB) of every video file on the
    card — minutes of cold reads with no timeout. Hardened with
    bounded budgets: camera-meta probes sample at most 3 clips, file
    reads run on a detached thread with a 10 s budget, resolution
    carries a 60 s overall budget (degrading to pattern → label →
    "unknown"), and the whole card scan is capped at 120 s. The chain
    now logs per-step progress. The converter's clip probe is likewise
    capped at 3 camera-meta probes per group.
  - Fix all card file lists scrolling together (ltc-gui): every card's
    scroll area shared one egui id, so scrolling one card scrolled all
    of them in lockstep; cards are now id-salted per mount path.
  - Fix Windows cross-compile: DRIVE_* constants (windows-sys 0.59)
    referenced from the wrong module path.
- Convert tab:
  - Fix converter sometimes dropping the wrong track as LTC: the
    ltc-gui decode-section track selector never propagated to the
    engine, so conversion kept dropping track 1 even when another
    track was selected and decoded (the offload→converter handoff hit
    exactly this, silently losing a production-audio track). Track
    selection is now engine-synced, auto-derived from the decoded
    file's position in the group, and LTC dropping matches the input
    index so it stays correct under permuted channel maps.
  - Fix output folder re-defaulting only on the first recording: the
    GUI's settings-reconcile loop echoed engine-initiated folder
    changes back as user edits, permanently freezing the folder;
    engine-initiated changes are now adopted, never echoed back.
- Misc:
  - The default log filter is now defined once in gui-engine
    (log_buffer.rs), unifying the project log level at debug.

* v0.4.6

Main features are a faster, more reliable card-offload workflow —
per-file selection with recording dates and durations, byte-accurate
progress with copy-speed display, a responsive cancel, and fixed card
detection on both Linux and Windows — plus converter fixes that stop
settings fields reverting every frame, silent zero-step audio
conversions, and a default output folder that follows the source
clips.

List of Changes:
- Offloading:
  - Per-file selection in the card list: each detected card shows its
    files (name, recording date, duration, size) with per-file
    checkboxes and All/None/Latest-day quick actions; selection
    defaults to all files from the most recent recording day and only
    selected files are copied. Files are listed newest-first.
  - Copy performance & progress: chunked 1 MiB copy raises throughput
    from ~0.3 MB/s to disk-bound; byte-based progress (with GB
    totals) moves within large files instead of jumping per file;
    both GUIs show the file being copied and an EMA-smoothed speed.
  - Responsive cancel: checked per chunk (takes effect within ~1 MiB),
    deletes the .offload_tmp partial, marks the device Skipped, and
    the UI shows "Canceled by user" instead of "Offload complete".
  - Linux card scan now finds udisks2 automounts (/run/media was
    wrongly excluded), auto-mounts unmounted removable cards via
    udisksctl, classifies card readers by sysfs removable flag or
    usb/mmc bus (internal disks no longer offered as cards), and
    fixes base-device derivation for nvme*/mmcblk* partitions.
  - Windows card scan no longer hangs: drives enumerated via
    GetLogicalDrivesW/GetDriveTypeW instead of per-letter exists()
    probes (which blocked on network drives/empty slots), non-
    removable drives and symlinks/junctions skipped, scan lifecycle
    logged end-to-end, scan-thread panics caught so "Scanning" can't
    latch.
- Convert tab:
  - Stop settings fields reverting every frame: ltc-gui syncs edits
    via a three-way merge against the previous engine snapshot (edited
    fields win, untouched adopt engine changes); ltc-slint pushes text
    on focus loss. Filename prefix no longer prefilled from the
    recording (starts at the {device} default); output folder defaults
    to the selected recording's parent dir instead of the scan root
    and is no longer persisted across sessions.
  - Fix audio-only conversions silently running zero ffmpeg steps:
    the MultiTrackAudio channel map is sized by the group's file count
    (not the first clip's probe channel count), stale dimensions are
    repaired at conversion time, and a zero-step plan now fails the
    conversion instead of reporting success. ltc-slint decodes the
    selected LTC source file instead of always the first.
- ltc-gui:
  - Fix text-field cursor jumping behind typed characters: typed
    fields (clapper ROLL, offload folder/device names, converter
    output folder/prefix/suffixes) use a GUI-owned persistent edit
    buffer that adopts the engine value only when unfocused; ROLL now
    commits per keystroke.

* v0.4.5

Main features are embedded camera metadata in converter outputs, a {device}
name template for output naming, moving all converter/offload state
ownership into the gui-engine, and subprocess robustness — timeouts and
stall watchdogs for all ffmpeg/ffprobe/exiftool probes.

List of Changes:
- Convert tab:
  - Embed camera metadata in converted outputs: make/model (com.apple.quicktime.*
    for MOV), lens, serial, gamma, creation date on video outputs; bext
    originator/origination_date/description on WAVs. New "Embed camera metadata"
    toggle (default on) + detected-camera readout in both GUIs.
  - Fall back to the camera-native start timecode (XAVC LtcChangeTable /
    AVCHD H264:TimeCode) when LTC decoding finds no timecode for a file;
    warn when both exist and differ.
  - New {device} naming placeholder for the detected recording device
    (XAVC binary sniff -> camera metadata probe -> filename pattern ->
    "unknown"); it is the new default filename prefix and works in suffix
    templates. The duplicate-output warning now suggests {device}.
  - Warn (never block) when two output files resolve to the same name —
    templates without {clip}/{track}/{filename} previously let ffmpeg
    silently overwrite earlier outputs.
  - Honour "concatenate audio" in the Metadata Only pipeline: multi-clip
    video sequences now emit one concatenated audio file per track instead
    of per-clip files; preview and collision warning reflect this.
  - Fix auto-select race: SelectRecording(0) sent right after SelectFolder
    raced the async folder scan, so the first recording was never probed;
    the engine now defers it until the scan arrives (removed the ltc-slint
    100ms timer hack).
- Engine robustness:
  - All ffprobe/exiftool probes run with a 10s timeout; ProbeVideo moved to
    a generation-stamped background thread — corrupt inputs can no longer
    hang the whole engine (frozen clock, stalled commands).
  - 30s no-output stall watchdog for streaming ffmpeg calls (audio
    extraction, conversion steps) and bounded timeouts for CLI extraction
    and tagger remux, so cancellation works even when ffmpeg is silent.
- Refactoring (state ownership):
  - Move all converter state into gui-engine as the sole source of truth:
    engine-owned ConverterUserSettings, fine-grained ConverterCommand
    variants, config persistence/restore, defaults repair on ffmpeg-capability
    arrival, prefix prefill, channel-map resize, readiness/output-preview
    recompute, engine-driven StartConversion/CancelConversion.
  - Migrate ltc-slint converter & offload handling fully onto the engine
    (deleted local Arc<Mutex> state, ~700 lines).
  - Fix ltc-gui settings-sync regression: toggles are diffed against the
    snapshot and sent as commands instead of reverting every frame.
- Offloading:
  - Auto-detect camera model from clip metadata (exiftool, ffprobe-tag
    fallback) when scanning cards — e.g. Sony FS100 auto-names as
    NEX-FS100EK instead of pattern-derived "FS100".
  - Remember the last used offload parent directory across sessions.
