#+TITLE: Version History for LTC Timecode Generator

* v0.5.5

Minor patch to disallow the combination of MOV + AV1 in the conversion GUI, as
ffmpeg does not support it.

List of Changes:
- Converter: The previously allowed combination of MOV + AV1 is now disallowed,
  as it is unsupported by ffmpeg.
- Logging: Ffmpeg arguments and error messages now appear in the app's debug
  log to make bug reports easier to debug.

* v0.5.4

Main features are LTC encoder robustness (WP-EN): drift-free file renders at
fractional frame rates, calibrated output levels with dBFS presets, and a
standards-permitted clock-preamble lead-in that protects the first LTC frame
from a recorder's input settling window.

List of Changes:
- Encoder/CLI: WAV renders (--output-to-file) now use the same fractional-
  sample accumulator as the live scheduler, so renders at fractional fps no
  longer drift against wall clock (29.97 fps @ 48 kHz previously gained
  +120 samples per 10 s = +1.79 s per 2 h; 24 fps @ 44.1 kHz +0.5 samples
  per frame). Integer-rate renders are bit-identical.
- Levels: --volume is now optional with per-mode defaults — file renders
  default to 0.5 UI (−12 dBFS peak, a safe-hot reference level that buys
  decoder SNR headroom), live playback stays at 0.25 UI (−24.1 dBFS). Both
  GUIs gain −18/−12/−6 dBFS preset buttons and a live dBFS readout beside
  the LTC volume slider.
- Lead-in: playback and renders now begin with one frame's worth of
  alternating bi-phase clock bits (no sync word, no timecode) so a
  recorder's AGC/HPF settling window cannot swallow the first real LTC
  frame. Under a measured 250 ms settle ramp with chain noise the builtin
  decoder previously lost the first two frames; with the preamble all
  frames decode starting at the start TC (libltc head loss likewise fixed;
  its documented tail loss is unaffected). The preamble carries no codeword
  and cannot pollute trim-to-first-LTC flows.
- CI/Testing: mutant-run hardening (sharded OOM-safe cargo-mutants runs,
  weekly CI audit), clippy 1.96 lint fixes under the -D warnings gate,
  MSRV/advisory checks, and a unit-test backfill recovering the Sonar
  new-code coverage gate.

* v0.5.3

Main features are a permanent real-world decode-test asset (WP-RW) — a corpus
sweep harness plus committed fixtures covering signal classes no synthetic test
produces. The decoder fix immediately paid for itself: frame detection now
re-locks after bitstream shifts, which cures a collapse class where long or
disturbed recordings lost everything after the first glitch.

List of Changes:
- Decoder: glitch-recovery - frame detection decodes along the dominant
  80-bit alignment grid only, so a single drop-out or noise burst that
  shifted the extracted bitstream permanently orphaned every later
  frame. Accepted sync words now chain re-lock (80-bit-spaced runs with
  consecutive timecodes), grid decoding stays as the noise baseline,
  and the fast-path gate uses grid-only confidence so chain-recovered
  counts cannot skip the detailed decode. On the 49-minute real-world
  reference recording: chunked decode 92.2% to 99.9%, worst degraded
  chunk 62.4% to 99.6%, --single-pass 58.7% (first 4 minutes lost,
  LowConfidence) to 99.9% Success with the full span; the whole-corpus
  sweep's worst file went from 68.8% LowConfidence to 99.3% Success
  and all five recording days now pass the timeline oracle cleanly.
  All WP-DR robustness cliff pins pass unchanged.
- Testing: a corpus sweep example harness (ltc-corpus-sweep) decodes
  the local recording corpus end to end, classifies every file by
  filename pattern, checks per-day cross-device timeline consistency
  (measurement only — exit 0 on a completed sweep), and emits version-
  diffable JSON. The committed corpus fixtures pin the field signal
  classes at every test layer: 24-bit PCM WAV, 16-bit big-endian LPCM
  in MP4, lossy AAC LTC in m4v, and a real mic track as non-LTC
  negative (LTC must survive lossy coding — previously unassertable).
  Known limitation surfaced and pinned: libltc's binding is 16-bit-
  only, so it cannot decode the 24-bit fixtures or the video
  extraction pipeline's 24-bit output; cross-backend agreement is
  asserted on 16-bit material.
- Decoder: wrong-value robustness up 2x+ - a new value-integrity pass
  validates every decoded frame against LTC's BCD digit ranges and
  frame-rate bounds, repairs single-frame outliers from their coherent
  neighbours, and drops unverifiable garbage instead of reporting it
  with confidence. Gaussian noise up to std 0.31 (was 0.18) and click
  density up to 5.6% (was 0.4%) now decode with correct values.
- Decoder: DC-offset and mains-hum immunity - decode input is
  conditioned (median click filter, DC removal, 50/60 Hz mains notches)
  before detection, so offsets up to 16x the signal amplitude and hum
  up to the measurement cap decode correctly (previously the cliff was
  offset/hum at about 1x signal). Quieter signals decode too: the
  minimum volume dropped from 0.0104 to 0.0041.
- Decoder: a decode left with no usable timecode values (periodic
  non-LTC content that merely sync-matches) no longer claims Success,
  and the quality report no longer scores a degenerate single-frame
  decode as usable. Decode runtime stays well within 2x of the
  previous release on both decoders.


* v0.5.2

Main feature is a tag-driven release pipeline: pushing a strict
vX.Y.Z tag now builds the official ship matrix in CI and publishes a
GitHub Release with the matching VERSION_LOG.org entry as the release
body, replacing the manual build-and-copy ritual for public
distribution. The pipeline was rehearsed end to end with the
workflow's dry-run mode before this release.

List of Changes:
- Release pipeline: a new GitHub Actions workflow (release.yml) runs on
  vX.Y.Z tag pushes — a guard job enforces the strict tag pattern,
  checks the tag against the workspace version, and extracts the
  VERSION_LOG.org release notes; two parallel build jobs produce the
  linux x64 and windows x64 artifacts; a release job assembles
  checksums and publishes the GitHub Release. A workflow_dispatch
  dry-run mode rehearses the whole pipeline on a branch without
  publishing.
- Statically linked libltc in all shipped binaries: a new build script
  (scripts/build-libltc-static.sh) builds a static-only libltc prefix
  from the pinned v1.3.2 source release, shared by CI, the local
  release script, and the documented manual recipe. Released binaries
  no longer depend on libltc.so at runtime.
- glibc 2.31 floor for the linux x64 artifact: the CI release job and
  the local build script both build via cargo-zigbuild with an
  explicit 2.31 target, and the workflow verifies the binary's maximum
  required GLIBC symbol version.
- Local release script rewritten (build-all-rust-targets.sh): ships
  linux x64 + windows x64 with static libltc and the glibc floor; the
  i686 tablet target is no longer part of the official matrix and
  remains a manual docker speciality (the builder image was fixed to
  carry a pinned static libltc again, so it compiles after the
  libltc-rs migration).
- CI fixes surfaced by the rehearsal: the windows-tests job now runs
  nextest against the shipped x86_64-pc-windows-gnu target (previously
  it silently targeted the host msvc toolchain, where the mingw libltc
  setup never applied, and had never passed); bindgen in the release
  jobs gets its libclang and include paths pinned explicitly
  (zigbuild and backslash-mangling issues); and two latent Windows
  test bugs were fixed (a /tmp output folder and an SVT-AV1 fixture
  encoder that the CI ffmpeg build lacks).
- Documentation: README gained a Releases section (assets, trigger,
  forward-only policy, i686 exclusion, dry-run rehearsal, tag
  hardening), and AGENTS.md documents the pipeline and the new
  scripts.


* v0.5.1

Main features are a smoother clapper-board animation on both desktop
apps and the formalisation of the project's error-handling policy.

List of Changes:
- Clapper animation: the clap flash and the slate arm used to be
  stepped by the engine's 25 fps background tick, so they could only
  ever move that fast no matter how often the window repainted. The
  engine now publishes a monotonic clap_seq counter that simply
  announces each clap, and each app animates at its own full frame
  rate: ltc-gui runs a GUI-local animator (clap_anim.rs, decay
  curves relocated from the engine, sampled at the GUI frame rate
  with self-requested repaints), while ltc-slint pulses a one-shot
  flash-strike trigger and animates the decay declaratively. All
  engine-owned animation state was removed from the published
  snapshot. Clap behaviour itself — beep, log entry, take numbering —
  is unchanged.
- CLI: the list-devices output formatting was extracted into a
  testable formatter.
- Documentation: AGENTS.md gained a normative Error-Handling Policy
  section (typed errors at decision points, cancellation as a variant
  instead of an error string, String only at display boundaries, and
  the migration/classification rules for remaining Result<_, String>
  sites), with the full inventory kept in a local report.


* v0.5.0

Main features are a workspace-wide quality campaign: the engine and
audio-core were decomposed into small, unit-tested components behind
typed errors and a unified background-job system; the GUI↔engine
interaction was reworked onto a shadow-state model with exact command
acknowledgement, eliminating the class of races where a stale engine
snapshot overwrote a fresh edit; five verified correctness defects
were fixed (WAV fmt-scan endianness, MP4 tmcd stco offset, the
cross-decoder confidence scale, drifted video-extension lists,
unbounded subprocess probes) along with follow-up fixes to decoding,
conversion progress and offload behaviour; the startup ffmpeg
capability probe no longer blocks on hardware-encoder validation; and
the legacy React web app, both Tauri crates and the entire Node/npm
toolchain were retired in favour of a Rust-only workspace. The project
also gained continuous integration (GitHub Actions with clippy,
coverage and SonarQube Cloud quality-gate enforcement) and
first-class Windows and macOS CI platforms.

List of Changes:
- Correctness fixes (each developed with a failing test first):
  - WAV fmt-scan endianness: the bext tagger read RIFF chunk sizes
    big-endian, so any WAV with a chunk preceding `fmt ` (LIST/JUNK
    from recorders) failed with "no fmt chunk found", and the sample
    rate was read from the wrong payload offset; scanning is now one
    little-endian, padding-aware reader that no longer assumes `fmt `
    is the first chunk.
  - MP4 tmcd stco patch: the native in-place MP4 timecode tagger
    shipped the tmcd track's stco chunk offset as 0, so spec-strict
    tools resolved the timecode sample to garbage; the offset is now
    patched to the appended mdat payload position and verified by an
    end-to-end ffmpeg+ffprobe round-trip fixture test.
  - Cross-decoder confidence contract: libltc stored avg_confidence
    as a 0–100 percentage (displayed 100× too high) and never
    classified LowConfidence, while the builtin used a 0.0–1.0
    fraction; both decoders now publish the same 0.0–1.0 scale with
    shared threshold constants and a contract test over the
    real-world fixture.
  - Video-extension registry: the video-extension list had drifted
    across five call sites (an .m4v was ingested by offload but
    rejected by path_is_video()); a single VIDEO/AUDIO_EXTENSIONS
    registry now backs all media classification and stream-copy
    container mapping.
  - Subprocess hygiene: the udisksctl mount call and the VAAPI/Vulkan
    hardware probes ran unbounded (a stuck helper hung the card scan
    or the startup probe forever); all remaining bare spawns —
    udisksctl, hardware probes, `ffmpeg -version`, the encoder/format
    list probe — now run through the shared timeout runner,
    surfacing as a converter-unavailable error within 10 s per probe,
    with list-probe failures logged instead of silent and the list
    parsing extracted into a unit-tested function.
  - Conversion progress no longer reaches 100% while ffmpeg steps are
    still in flight (the in-flight step's fraction is capped below
    its full weight).
  - Offload/engine edge cases: the offload→converter handoff fires
    only when copy devices actually completed; zero-length group
    durations are treated as unknown; the playback volume mapping
    clamps its input to 0..1; and offload collision renaming assigns
    its "name (2).ext" suffixes in sorted order so duplicates resolve
    deterministically.
- Decoder improvements: the builtin decoder now decodes the first and
  last frames of a file (previously dropped by the search windows)
  and the chunked libltc path is exactly equal to direct libltc
  decoding; WAV LTC decode auto-selects a non-silent channel when the
  configured channel carries no signal; and cancellation is a typed
  signal threaded through audio-core into gui-engine (asserted as
  variants, not text).
- Unified async-job system: all background tasks (conversion, offload
  scan/copy, LTC decode, folder scans, clip/duration/capability
  probes) run behind one JobSupervisor/spawn_job infrastructure with
  weighted per-unit progress, cancellation tokens, EMA speed
  metering, capped log capture, stale-result gating (events from
  superseded jobs are rejected) and duplicate-spawn guards;
  per-chunk decode progress is bridged into job units, and copy
  speed plus per-drive scan messages are reported from it.
- Engine decomposition (gui-engine): the tick loop's twelve
  loop-carried locals collapsed into EngineLoopState; job-event
  dispatch matches exhaustively on JobKind with named per-kind
  handlers (a new kind without a handler is a compile error) and a
  single process_command site owns the full GuiCommand match;
  fourteen copy-paste converter setters collapsed into one
  table-tested helper; the CLI and GUI share one decode pipeline
  (decode.rs) instead of two near-copies, with the
  single-pass-vs-chunked WAV-decode dispatch unified in
  decode_wav_core behind a pure decision helper; idle ticks no longer
  deep-clone the snapshot (the unchanged-publish gate compares before
  cloning); dead plumbing was removed and conversion step failures
  are recorded into the job log.
- audio-core restructuring: lib.rs became a ~70-line front door with
  types/wav_chunk_reader/chunked_decode modules and one chunk-boundary
  planner (fixing ±1 chunk-count predictions in the gui-engine
  progress totals); decoder backend selection is a trait LtcDecoder
  seam; chunked decoding is decomposed into plan/run/merge units over
  a mockable decoder; device enumeration has a single probe path; the
  callback-stall recovery is a pure, virtual-clock-tested watchdog
  state machine; the decoder strategy ladder and the LTC quality
  score are decomposed into directly unit-tested pure functions; and
  the dead API surface (quick_check_ltc and friends) was removed.
- Converter consolidation: one channel-map/drop iteration
  (selected_channel_pairs) replaces six drifted copies (the concat
  fallback now respects the channel map too); output preview and
  collision warning become projections of plan_output_paths, so
  preview and execution agree on LTC dropping and the warning covers
  concat/synthetic/passthrough outputs; the metadata-only pipeline is
  decomposed into probe/extract/tag+rename/summarize phases with real
  failure accounting — StepFailure details reach the UI and a fully
  failed run no longer reports success; one ffmpeg stderr-watchdog
  driver and one ffprobe JSON helper replace the duplicated
  epilogues; and the camera→WAV-bext field mapping lives in a single
  bext_meta module (originator constant, description mapping, mtime
  date fallback).
- Shadow-state GUI interaction: every interactive widget in both GUIs
  renders from a typed EditState shadow synchronised against engine
  truth with an exact echo acknowledgement (applied_command_seq),
  replacing the value-echo and three-way-merge machinery;
  engine-initiated setting changes propagate through the same sync;
  offload device-folder renaming is addressed by mount path so a
  rescan cannot retarget the wrong card; fixed ltc-slint bugs (dead
  converter focus gate, the ROLL TextInput losing keystrokes,
  prefix/suffix inputs detaching from engine updates after the first
  keystroke).
- Published-state audit: dead snapshot fields removed (per-tick
  generation counter, wake-lock flag and chip, write-only and
  set-only fields, the no-op "Trim to first LTC frame" toggle, the
  decorative naming-pattern selector, system_time); channel routing
  is a ChannelSel enum end-to-end, FPS a single index with accessors,
  the quality grade an enum; decode and clapper fields regrouped into
  sub-structs; audio devices are selected by stable id so re-scans
  can no longer silently repoint the selection; the global
  status_message became per-subsystem StatusChannels and audio events
  are delivered via a one-shot channel instead of the snapshot; and
  all pre-existing clippy warnings were fixed.
- Typed errors: CLI timecode/device-resolution failures, ffprobe and
  subprocess probe errors, audio-core chunk/bit-depth/watchdog
  payloads, conversion checks (ConversionCheckError plus a
  FailureLedger that makes a nothing-succeeded run end Failed),
  stream selection, offload planning, skip reasons, tagging errors
  and probe status labels are typed variants instead of formatted
  strings; the matching message-text test pins were rewritten to
  typed assertions and JobOutcome::Failed gained a typed panic flag.
- Startup capability probe: per-stage timing instrumentation plus a
  `--probe-caps` report mode; hardware encoders are withheld from the
  initial capability publication and validated by a background
  test-encode job that reconciles the list and republishes — a broken
  GPU/driver can no longer stall startup, no codec loses its encoder
  chain (every codec keeps a software fallback) and readiness never
  blocks; validated passes are cached (keyed on ffmpeg version,
  encoder list and hardware devices; failures are never cached; a
  corrupt cache file is ignored) so repeat startups publish validated
  hardware encoders immediately; when validation newly enables a
  hardware encoder and the user has not touched container/encoder
  settings this session, the engine re-picks the best default
  combination.
- Complexity burn-down: the SonarCloud CRITICAL census (29 × S3776
  cognitive-complexity smells + 1 × wildcard import) was cleared by
  decomposing the ltc-slint `_run_gui`/`setup_poll_timer`
  mega-functions into per-concern register_/sync_ helpers (the
  9-parameter poll signature is gone; static converter models are
  built once instead of every tick), splitting the ltc-gui converter,
  app-logic, clock, offload, settings and status hotspots into render
  helpers plus pure unit-tested extractors, and extracting pure cores
  from engine and audio-core hotspots (file-pattern matching,
  converter runner/planning/args, card-detection mount filtering,
  engine loop and command dispatch, CLI decode-report rendering, the
  stderr watchdog, the scheduler loop, the decode search lattice,
  libltc assembly) — +140 unit tests, logic moved verbatim behind
  characterization tests; the tagger's wildcard imports were made
  explicit.
- Test infrastructure: offload card detection is injectable
  (EngineSeams) with engine-thread integration tests for the full
  offload pipeline, the SetDevice bogus-id revert and the audio
  recovery ladder (init failure forced deterministically; the attempt
  counter is published as audio_recovery_attempts); a committed MP4
  fixture plus round-trip suite guards the native tmcd tagger;
  process_cli_result returns a Result instead of exiting the process
  (new tests/cli_decode.rs covers output-to-file, WAV/video decode
  and the error paths); deadline-poll loops replace fixed sleeps;
  message-text pins, duplicate, tautological and can-never-fail tests
  were rewritten or deleted and process_command received unit-test
  backfill; offload integration tests serialize their config access;
  coverage of the named files rose to cli.rs 63% (from 46%),
  offload 92%, tagger 90%, engine 84%; the test-lint guardrail
  (sleep/text-pin rules) runs in CI with a --self-test mode;
  .config/nextest.toml dropped keys nextest ignored; AGENTS.md gained
  the Test Quality rules, the plan-folder convention and the
  never-weaken-a-failing-test policy.
- Continuous integration and quality gate: a GitHub Actions pipeline
  runs the test-lint guardrail, clippy (JSON report imported by
  Sonar), the test suite with coverage (cargo llvm-cov nextest +
  LCOV) and the SonarQube Cloud scan (skipped without SONAR_TOKEN, so
  forks run plain CI); the idempotent sonar-gate script creates the
  LTC gate (new-code coverage > 80%, reliability/security/
  maintainability ratings A) and CI passes
  -Dsonar.qualitygate.wait=true so a failing gate reds the pipeline;
  an overall-code enforcement step (sonar-overall-gate.sh with
  self-test fixtures) reds main on overall-code violations (ratings
  ≤ A, duplication < 3%, hotspots 100% reviewed); the report script
  gained a per-condition new-code table, numeric rating rendering and
  jq payload handling via file; the first gated scan passed with
  every new-code condition green (new-code coverage 91.8%); assorted
  runner fixes en route (missing audio/fontconfig/PipeWire/Pulse dev
  libraries, cargo-llvm-cov ≥ 0.9 subcommand rename, cache action
  bump, macOS Homebrew bindgen include path).
- Legacy frontend retirement and version management: the React web
  app, both Tauri crates and the entire Node/npm toolchain were
  removed (pure subtraction — the shipped ltc-gui matrix of linux
  x64, windows x64 and linux i686 is unaffected); the version source

- Windows and macOS CI platforms: windows-cross-check compile-guards

* v0.4.7

Main features are a hardened, more responsive card-offload workflow —
live per-drive scan status, a non-blocking Start button, fixed
multi-file progress/speed reporting, an end to the endless card-scan
hang on FS100 (AVCHD) cards, and per-card scroll isolation — plus a
converter fix that stops the wrong track being dropped as LTC.

List of Changes:
- Offloading:
  - Fix progress/speed reporting for multi-file copies: the bar froze
    during files 2..N with speed reading 0 MB/s, then jumped by a whole
    file's share on completion (and could clamp at 100% early).
    Per-file deltas are now reported correctly; per-device byte
    counters use AtomicU64 so cards over 4 GiB no longer wrap on
    32-bit builds; the speed EMA no longer collapses to 0 MB/s during
    fsync/verify pauses between files.
  - Live scan status: the static "Scanning…" indicator is replaced by
    per-drive messages (e.g. "Scanning drive EOS_DIGITAL
    (/run/media/…)…"), covering the Linux auto-mount phase too, shown
    in the Offload tab and status bar of both GUIs.
  - Start Offload is non-blocking: copy plans are built from the sizes
    already collected during the card scan (zero I/O) instead of
    stat'ing every file on the card on the engine thread — the
    Start→Cancel switch is instant and the engine no longer stalls;
    ltc-gui also repaints continuously while an offload is pending or
    running (fixing the 1 Hz progress bar).
  - Fix endless card-scan hang on FS100 (AVCHD) cards: device-name
    resolution read the head+tail (8 MB) of every video file on the
    card — minutes of cold reads with no timeout. Hardened with
    bounded budgets: camera-meta probes sample at most 3 clips, file
    reads run on a detached thread with a 10 s budget, resolution
    carries a 60 s overall budget (degrading to pattern → label →
    "unknown"), and the whole card scan is capped at 120 s. The chain
    now logs per-step progress. The converter's clip probe is likewise
    capped at 3 camera-meta probes per group.
  - Fix all card file lists scrolling together (ltc-gui): every card's
    scroll area shared one egui id, so scrolling one card scrolled all
    of them in lockstep; cards are now id-salted per mount path.
  - Fix Windows cross-compile: DRIVE_* constants (windows-sys 0.59)
    referenced from the wrong module path.
- Convert tab:
  - Fix converter sometimes dropping the wrong track as LTC: the
    ltc-gui decode-section track selector never propagated to the
    engine, so conversion kept dropping track 1 even when another
    track was selected and decoded (the offload→converter handoff hit
    exactly this, silently losing a production-audio track). Track
    selection is now engine-synced, auto-derived from the decoded
    file's position in the group, and LTC dropping matches the input
    index so it stays correct under permuted channel maps.
  - Fix output folder re-defaulting only on the first recording: the
    GUI's settings-reconcile loop echoed engine-initiated folder
    changes back as user edits, permanently freezing the folder;
    engine-initiated changes are now adopted, never echoed back.
- Misc:
  - The default log filter is now defined once in gui-engine
    (log_buffer.rs), unifying the project log level at debug.

* v0.4.6

Main features are a faster, more reliable card-offload workflow —
per-file selection with recording dates and durations, byte-accurate
progress with copy-speed display, a responsive cancel, and fixed card
detection on both Linux and Windows — plus converter fixes that stop
settings fields reverting every frame, silent zero-step audio
conversions, and a default output folder that follows the source
clips.

List of Changes:
- Offloading:
  - Per-file selection in the card list: each detected card shows its
    files (name, recording date, duration, size) with per-file
    checkboxes and All/None/Latest-day quick actions; selection
    defaults to all files from the most recent recording day and only
    selected files are copied. Files are listed newest-first.
  - Copy performance & progress: chunked 1 MiB copy raises throughput
    from ~0.3 MB/s to disk-bound; byte-based progress (with GB
    totals) moves within large files instead of jumping per file;
    both GUIs show the file being copied and an EMA-smoothed speed.
  - Responsive cancel: checked per chunk (takes effect within ~1 MiB),
    deletes the .offload_tmp partial, marks the device Skipped, and
    the UI shows "Canceled by user" instead of "Offload complete".
  - Linux card scan now finds udisks2 automounts (/run/media was
    wrongly excluded), auto-mounts unmounted removable cards via
    udisksctl, classifies card readers by sysfs removable flag or
    usb/mmc bus (internal disks no longer offered as cards), and
    fixes base-device derivation for nvme*/mmcblk* partitions.
  - Windows card scan no longer hangs: drives enumerated via
    GetLogicalDrivesW/GetDriveTypeW instead of per-letter exists()
    probes (which blocked on network drives/empty slots), non-
    removable drives and symlinks/junctions skipped, scan lifecycle
    logged end-to-end, scan-thread panics caught so "Scanning" can't
    latch.
- Convert tab:
  - Stop settings fields reverting every frame: ltc-gui syncs edits
    via a three-way merge against the previous engine snapshot (edited
    fields win, untouched adopt engine changes); ltc-slint pushes text
    on focus loss. Filename prefix no longer prefilled from the
    recording (starts at the {device} default); output folder defaults
    to the selected recording's parent dir instead of the scan root
    and is no longer persisted across sessions.
  - Fix audio-only conversions silently running zero ffmpeg steps:
    the MultiTrackAudio channel map is sized by the group's file count
    (not the first clip's probe channel count), stale dimensions are
    repaired at conversion time, and a zero-step plan now fails the
    conversion instead of reporting success. ltc-slint decodes the
    selected LTC source file instead of always the first.
- ltc-gui:
  - Fix text-field cursor jumping behind typed characters: typed
    fields (clapper ROLL, offload folder/device names, converter
    output folder/prefix/suffixes) use a GUI-owned persistent edit
    buffer that adopts the engine value only when unfocused; ROLL now
    commits per keystroke.

* v0.4.5

Main features are embedded camera metadata in converter outputs, a {device}
name template for output naming, moving all converter/offload state
ownership into the gui-engine, and subprocess robustness — timeouts and
stall watchdogs for all ffmpeg/ffprobe/exiftool probes.

List of Changes:
- Convert tab:
  - Embed camera metadata in converted outputs: make/model (com.apple.quicktime.*
    for MOV), lens, serial, gamma, creation date on video outputs; bext
    originator/origination_date/description on WAVs. New "Embed camera metadata"
    toggle (default on) + detected-camera readout in both GUIs.
  - Fall back to the camera-native start timecode (XAVC LtcChangeTable /
    AVCHD H264:TimeCode) when LTC decoding finds no timecode for a file;
    warn when both exist and differ.
  - New {device} naming placeholder for the detected recording device
    (XAVC binary sniff -> camera metadata probe -> filename pattern ->
    "unknown"); it is the new default filename prefix and works in suffix
    templates. The duplicate-output warning now suggests {device}.
  - Warn (never block) when two output files resolve to the same name —
    templates without {clip}/{track}/{filename} previously let ffmpeg
    silently overwrite earlier outputs.
  - Honour "concatenate audio" in the Metadata Only pipeline: multi-clip
    video sequences now emit one concatenated audio file per track instead
    of per-clip files; preview and collision warning reflect this.
  - Fix auto-select race: SelectRecording(0) sent right after SelectFolder
    raced the async folder scan, so the first recording was never probed;
    the engine now defers it until the scan arrives (removed the ltc-slint
    100ms timer hack).
- Engine robustness:
  - All ffprobe/exiftool probes run with a 10s timeout; ProbeVideo moved to
    a generation-stamped background thread — corrupt inputs can no longer
    hang the whole engine (frozen clock, stalled commands).
  - 30s no-output stall watchdog for streaming ffmpeg calls (audio
    extraction, conversion steps) and bounded timeouts for CLI extraction
    and tagger remux, so cancellation works even when ffmpeg is silent.
- Refactoring (state ownership):
  - Move all converter state into gui-engine as the sole source of truth:
    engine-owned ConverterUserSettings, fine-grained ConverterCommand
    variants, config persistence/restore, defaults repair on ffmpeg-capability
    arrival, prefix prefill, channel-map resize, readiness/output-preview
    recompute, engine-driven StartConversion/CancelConversion.
  - Migrate ltc-slint converter & offload handling fully onto the engine
    (deleted local Arc<Mutex> state, ~700 lines).
  - Fix ltc-gui settings-sync regression: toggles are diffed against the
    snapshot and sent as commands instead of reverting every frame.
- Offloading:
  - Auto-detect camera model from clip metadata (exiftool, ffprobe-tag
    fallback) when scanning cards — e.g. Sony FS100 auto-names as
    NEX-FS100EK instead of pattern-derived "FS100".
  - Remember the last used offload parent directory across sessions.
- Misc:
  - Fix compiler/clippy warnings and repair the ltc-gui test build; port
    auto-apply-LTC tests into gui-engine.
  - Deterministic engine tests (predicate waits, fake ffmpeg probe,
    temp-dir config) + flaky-test detection via cargo-nextest
    (npm run test:flaky); methodology documented in AGENTS.md.

* v0.4.4

Main features are UI freeze fixes, improved LTC quality scoring, H.265 default
for the converter, and the first pass at an offloading tab for file import.

List of Changes:
- Decode:
  - Reworked LTC quality score to reflect sync usability — anchored on usable
    coverage (fraction of frames in blocks >=2s with <=1 frame drift), computed
    per-segment drift via least-squares fit, capped jump penalties, and added
    usable_coverage, block_count, worst_block_drift_frames, backward_jump_count
    fields.
  - Report end-to-end processing time for video decodes (previously only the
    LTC decode step was timed, hiding ffprobe/ffmpeg extraction cost).
  - Abort LTC decode promptly on cancellation — cancel flag now checked inside
    the decoder (ZC scan, sliding-window search, chunk loops) and chunk
    concurrency bounded to available_parallelism().
  - Unified chunk-count logic and progress tracking — replaced 3 hand-rolled
    chunk-count loops with audio_core::count_chunks_in_wav(), stored progress
    as DecodeProgress struct instead of raw atomics.
- Convert tab:
  - Set H.265/HEVC in MOV with PCM 24-bit as the default codec/container when
    an encoder is available, ahead of ProRes/DNxHD/H.264; MP4+AAC as second
    H.265 row for builds without a MOV muxer.
  - Show LTC probe failure instead of stuck "Probing…" — preserved per-file
    ffprobe error strings, published ltc_decode_error on failure, fell back
    to the first successful clip probe.
  - Split the monolithic converter.rs into a directory module with focused
    submodules (progress, channel_map, timecode, capabilities, formats,
    settings, planning, checks, args, process, runner).
- ltc-gui:
  - Stop UI freezes when switching recordings — moved folder scanning off the
    GUI thread to a background scanner thread; split conversion_sanity_check
    into pure validation (no IO) for per-frame rendering and a full check with
    existence validation for preflight/conversion start.
- Offloading:
  - First pass at an offloading tab for file import, with recording device
    detection to auto-name destination folders.

  - Fix LTC source selection stuck at "Probing…" for video clips — ordering
    bug where ProbeVideo was sent before SelectRecording, which wiped the
    probe state. Also send SelectFolder during restore before auto-selecting
    a recording; warn when SelectRecording references an unknown group.
  - Fix egui widget & scrollArea ID duplication when processing multiple
    recordings in one session.

  - Reset per-recording state (LTC decode report, conversion status,

* v0.4.1

Main features are codec-level video encoder selection with automatic hardware
fallback in the convert tab, a stream-copy mode that leaves video encoding
untouched, and audio device robustness improvements.

List of Changes:
- Convert tab:
  - Reworked video encoding to codec-level selection (av1, h264, h265, prores,
    dnxhd) with priority-ordered encoder chains — hardware encoders first,
    software fallbacks; failed encoders are skipped for the rest of the run and

    nvenc/qsv/amf/mf/v4l2m2m candidates.

  - Show recording duration in the recording dropdown menu.
  - Expandable LTC decode result details for clip groups in ltc-gui.
  - Multi-file recording sequences now produce per-file output names
    (C0004-audio-track1 instead of C0003-audio-track2).
  - More robust file pattern matching using named capture groups.
  - Bug fixes: encoder fallback chain never ran on encoder init failure;
    output file preview was wrong for video clip groups and conversion encoded
    every output twice with inconsistent audio numbering; LTC decoding &
    timecode handling in multi-clip video files; convert-tab state management
    bugs in both native GUIs (track selector stored in ephemeral frame state,
    now snapshot is read-only); file name collision detection now checks
    individual file names and is a warning instead of a blocking error;
    ffmpeg probe thread exited uncleanly.
- Audio & GUI robustness/performance:
  - Refactored audio-core (playback code extracted to audio_output.rs) and
    made device handling more robust: StreamDead now triggers full recovery,
    default buffer size selection, and stream playback starts only after the
    ring buffer is prefilled.
  - Fixed egui GUI performance: a broken clap-animation check caused constant
    immediate repaints (busy loop); the GUI now sleeps when idle.
  - Added a GUI performance measurement script (perf-test/) and an

- Misc:
  - Added Windows cross-compilation instructions for the libltc dependency to

  - Fixed clippy warnings.

* v0.3.1

Primary focus in this release is to improve stability when working with direct
device access for specific audio devices, instead of using the system
default. Hopefully this will significantly reduce the number of crashes of
audio output for directly selected devices.

List of Changes:

  that do not show in ALSA.
