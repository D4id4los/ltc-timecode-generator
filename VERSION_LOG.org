#+TITLE: Version History for LTC Timecode Generator

* v0.4.1

Main features are codec-level video encoder selection with automatic hardware
fallback in the convert tab, a stream-copy mode that leaves video encoding
untouched, and audio device robustness improvements.

List of Changes:
- Convert tab:
  - Reworked video encoding to codec-level selection (av1, h264, h265, prores,
    dnxhd) with priority-ordered encoder chains — hardware encoders first,
    software fallbacks; failed encoders are skipped for the rest of the run and
    the encoder actually used is reported on completion.
  - Added VAAPI & Vulkan hardware encoder support alongside the existing
    nvenc/qsv/amf/mf/v4l2m2m candidates.
  - Run a detailed ffmpeg capability probe at startup; both GUIs now only
    offer containers/encoders that actually work, with a label showing whether
    hardware acceleration is supported per encoding.
  - Added a "Leave Video Encoding Untouched" (stream copy) mode: audio tracks
    are still extracted, the video is not re-encoded; trim points snap to the
    nearest video keyframe and the embedded start timecode is re-anchored so
    it matches the first video frame.
  - Show recording duration in the recording dropdown menu.
  - Expandable LTC decode result details for clip groups in ltc-gui.
  - Multi-file recording sequences now produce per-file output names
    (C0004-audio-track1 instead of C0003-audio-track2).
  - More robust file pattern matching using named capture groups.
  - Bug fixes: encoder fallback chain never ran on encoder init failure;
    output file preview was wrong for video clip groups and conversion encoded
    every output twice with inconsistent audio numbering; LTC decoding &
    timecode handling in multi-clip video files; convert-tab state management
    bugs in both native GUIs (track selector stored in ephemeral frame state,
    now snapshot is read-only); file name collision detection now checks
    individual file names and is a warning instead of a blocking error;
    ffmpeg probe thread exited uncleanly.
- Audio & GUI robustness/performance:
  - Refactored audio-core (playback code extracted to audio_output.rs) and
    made device handling more robust: StreamDead now triggers full recovery,
    default buffer size selection, and stream playback starts only after the
    ring buffer is prefilled.
  - Fixed egui GUI performance: a broken clap-animation check caused constant
    immediate repaints (busy loop); the GUI now sleeps when idle.
  - Added a GUI performance measurement script (perf-test/) and an
    --autostart flag for benchmark runs.
- Misc:
  - Added Windows cross-compilation instructions for the libltc dependency to
    the README.
  - Fixed clippy warnings.

* v0.4

Main features are a new much more performant slint based GUI, a new convert
tab that allows loading audio or video files with an LTC track and use that to
produce clipped versions that have the correct timecode from LTC set, ready for
import into a video editing software, and a major overhaul of the LTC decoding
performance, robustness, and reporting.

List of Changes:
- Added Slint based GUI.
- Added convert tab to all GUIs.
- Refactored the shared GUI logic into a common gui-engine crate used by both
  native GUIs (audio lifecycle, state management, CLI, decoding, conversion).
- Major LTC decoding overhaul:
  - Chunked parallel decoding of large files with progress display and
    cancellation.
  - Improved robustness against clock drift, better fallback handling, and
    fixed phase-offset and chunk-overlap bugs.
  - Added a timecode quality measure/report (confidence, gaps, glitches) with
    a verbose CLI mode and copy-report buttons in the GUIs.
  - Added a CLI flag to list all decoded timecodes in a file.
  - Made the libltc decoder (--decoder libltc) selectable in the GUIs.
  - Filter out bogus timecodes at the start of files.
- Convert tab improvements:
  - Support video files for LTC track selection and decoding.
  - LTC-based trimming to the first detected timecode frame.
  - Auto-enable split tracks & drop LTC track after LTC detection.
  - Flexible user-defined file naming patterns for grouping input files.
  - Remember last used input & output folders.
- Unified and improved ffmpeg integration: single detection shared between
  GUIs, better format/encoder capability querying and defaults, fixed mkv
  detection, audio channel mapping, and split tracks on video files.
- Changed supported sample rates to 44100 and 48000 Hz.
- Fixed a bug in the TypeScript LTC generation, with regression tests in TS & Rust.
- Added extensive unit & integration tests for audio-core and gui-engine.
- Added clippy linting to the project and fixed warnings.
- Unified default settings and colour definitions between the Rust GUIs.
- Improved the version sync script to cover all crate manifests and lock files.

* v0.3.3

List of Changes:
- Added a command line argument flag to enable debug log output
- Added a sleep prevention functionality to the rust gui and the rust
  audio-core.

* v0.3.2

Main feature is a basic CLI interface that allows for headless running of the
LTC generator.

List of Changes:
- Gracefully handle a case where the device does not support the selected
  sample rate, and the audio-core chooses a different rate. The GUI will now
  receive the actually selected rate and correctly present this information.
- Fix the infinite loop of device reinitialisation after a audio devices
  callback crashed and all attempts fail. It will now make 3 attempts and then
  stop.
- Added a basic CLI to the rust GUI that allows for headless runs, performance
  testing, and creating WAV files with a LTC timecode.

* v0.3.1

Primary focus in this release is to improve stability when working with direct
device access for specific audio devices, instead of using the system
default. Hopefully this will significantly reduce the number of crashes of
audio output for directly selected devices.

List of Changes:

- Fix the version bumping script to actually commit the files it changes.
- Fix logging window resizing to allow arbitrary window sizes.
- Improve the querying and logging of the system's audio device's supported
  features.
- Make the audio-core code more robust when directly accessing devices through
  the cpal library, instead of using default audio devices that go through the
  entire linux audio stack.
- Make audio sample rate configurable between 16MHz and 48MHz, with the default
  value being calculated depending on the device's CPU (week CPUs prefer lower
  sample rate).
- Change beep length default to 500ms and make it configurable in the GUI.
- Added a version log file.
- Added a build script that builds all supported Rust targets.
- Created a local deploy to onedrive script, and added it to gitignore.
- Use PipeWire by default, then fall back to PulseAudio, then to ALSA/JACK as
  the audio backend. Allows detection of devices such as bluetooth headsets
  that do not show in ALSA.
- Small fix to the version bumping script which had a path problem.


* v0.3.0

Mayor re-design of the rust audio backend to be more supportive of direct audio
deivce access and support broader audio device requirements, instead of
hard-coding stuff like the data format.

Introduces a Rust-Based GUI for better performance on weaker devices.

Also contains a number of smaller changes:

- Create a Rust GUI.
- Changes to the default settings for audio levels, output channels, etc.
- Added logging to the Rust GUI & improved logging in the audio-core Rust backend.
- Performance improvements to the Rust LTC generation code.
- Make volume control more granular and weighted on a quadratic curve.
- Remove unsafe block in audio backend.
- Add windows cross compilation support.
- Added an in-gui log viewer window.
- Improve audio device selection error handling.
- Add toast status messages to both Rust and Web GUIs.
- Improve the version bumping script.
- Fix a delay at LTC stream start causing buffer underfills.
