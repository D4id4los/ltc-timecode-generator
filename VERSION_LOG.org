#+TITLE: Version History for LTC Timecode Generator


* v0.4.5

Main features are embedded camera metadata in converter outputs, a {device}
name template for output naming, moving all converter/offload state
ownership into the gui-engine, and subprocess robustness — timeouts and
stall watchdogs for all ffmpeg/ffprobe/exiftool probes.

List of Changes:
- Convert tab:
  - Embed camera metadata in converted outputs: make/model (com.apple.quicktime.*
    for MOV), lens, serial, gamma, creation date on video outputs; bext
    originator/origination_date/description on WAVs. New "Embed camera metadata"
    toggle (default on) + detected-camera readout in both GUIs.
  - Fall back to the camera-native start timecode (XAVC LtcChangeTable /
    AVCHD H264:TimeCode) when LTC decoding finds no timecode for a file;
    warn when both exist and differ.
  - New {device} naming placeholder for the detected recording device
    (XAVC binary sniff -> camera metadata probe -> filename pattern ->
    "unknown"); it is the new default filename prefix and works in suffix
    templates. The duplicate-output warning now suggests {device}.
  - Warn (never block) when two output files resolve to the same name —
    templates without {clip}/{track}/{filename} previously let ffmpeg
    silently overwrite earlier outputs.
  - Honour "concatenate audio" in the Metadata Only pipeline: multi-clip
    video sequences now emit one concatenated audio file per track instead
    of per-clip files; preview and collision warning reflect this.
  - Fix auto-select race: SelectRecording(0) sent right after SelectFolder
    raced the async folder scan, so the first recording was never probed;
    the engine now defers it until the scan arrives (removed the ltc-slint
    100ms timer hack).
- Engine robustness:
  - All ffprobe/exiftool probes run with a 10s timeout; ProbeVideo moved to
    a generation-stamped background thread — corrupt inputs can no longer
    hang the whole engine (frozen clock, stalled commands).
  - 30s no-output stall watchdog for streaming ffmpeg calls (audio
    extraction, conversion steps) and bounded timeouts for CLI extraction
    and tagger remux, so cancellation works even when ffmpeg is silent.
- Refactoring (state ownership):
  - Move all converter state into gui-engine as the sole source of truth:
    engine-owned ConverterUserSettings, fine-grained ConverterCommand
    variants, config persistence/restore, defaults repair on ffmpeg-capability
    arrival, prefix prefill, channel-map resize, readiness/output-preview
    recompute, engine-driven StartConversion/CancelConversion.
  - Migrate ltc-slint converter & offload handling fully onto the engine
    (deleted local Arc<Mutex> state, ~700 lines).
  - Fix ltc-gui settings-sync regression: toggles are diffed against the
    snapshot and sent as commands instead of reverting every frame.
- Offloading:
  - Auto-detect camera model from clip metadata (exiftool, ffprobe-tag
    fallback) when scanning cards — e.g. Sony FS100 auto-names as
    NEX-FS100EK instead of pattern-derived "FS100".
  - Remember the last used offload parent directory across sessions.
- Misc:
  - Fix compiler/clippy warnings and repair the ltc-gui test build; port
    auto-apply-LTC tests into gui-engine.
  - Deterministic engine tests (predicate waits, fake ffmpeg probe,
    temp-dir config) + flaky-test detection via cargo-nextest
    (npm run test:flaky); methodology documented in AGENTS.md.

* v0.4.4

Main features are UI freeze fixes, improved LTC quality scoring, H.265 default
for the converter, and the first pass at an offloading tab for file import.

List of Changes:
- Decode:
  - Reworked LTC quality score to reflect sync usability — anchored on usable
    coverage (fraction of frames in blocks >=2s with <=1 frame drift), computed
    per-segment drift via least-squares fit, capped jump penalties, and added
    usable_coverage, block_count, worst_block_drift_frames, backward_jump_count
    fields.
  - Report end-to-end processing time for video decodes (previously only the
    LTC decode step was timed, hiding ffprobe/ffmpeg extraction cost).
  - Abort LTC decode promptly on cancellation — cancel flag now checked inside
    the decoder (ZC scan, sliding-window search, chunk loops) and chunk
    concurrency bounded to available_parallelism().
  - Unified chunk-count logic and progress tracking — replaced 3 hand-rolled
    chunk-count loops with audio_core::count_chunks_in_wav(), stored progress
    as DecodeProgress struct instead of raw atomics.
- Convert tab:
  - Set H.265/HEVC in MOV with PCM 24-bit as the default codec/container when
    an encoder is available, ahead of ProRes/DNxHD/H.264; MP4+AAC as second
    H.265 row for builds without a MOV muxer.
  - Show LTC probe failure instead of stuck "Probing…" — preserved per-file
    ffprobe error strings, published ltc_decode_error on failure, fell back
    to the first successful clip probe.
  - Split the monolithic converter.rs into a directory module with focused
    submodules (progress, channel_map, timecode, capabilities, formats,
    settings, planning, checks, args, process, runner).
- ltc-gui:
  - Stop UI freezes when switching recordings — moved folder scanning off the
    GUI thread to a background scanner thread; split conversion_sanity_check
    into pure validation (no IO) for per-frame rendering and a full check with
    existence validation for preflight/conversion start.
- Offloading:
  - First pass at an offloading tab for file import, with recording device
    detection to auto-name destination folders.

* v0.4.3

Main features are a reworked set-start-time-from-LTC workflow that no longer
trims files, multi-clip recording fixes, and unified file naming.

List of Changes:
- Convert tab:
  - Replace "Cut and Set Start Time to First LTC Frame" with "Set Start Time
    from LTC" — conversions no longer cut the leading non-LTC region; instead
    the start timecode is computed from the first secure LTC frame (first
    frame of a >=2s run of consecutive, glitch-free timecodes) by counting
    frames back to the file start, and embedded via -timecode metadata.
    Outputs keep their full duration.
  - Fix LTC decode progress to work with multi-clip recordings (ffmpeg audio
    extraction + LTC detection both show progress).
  - Map audio channels instead of clips for videos: the channel mapping
    matrix now operates on audio channels of a clip; split/concat/mux all
    honor the mapping.
  - Refactor & unify file naming across preview and conversion via
    NameTemplate with named placeholders ({filename}, {clip:0Nd},
    {track:0Nd}).
  - Metadata-only mode: Added a mode that changes metadata and filename
    in-place, never re-encoding audio or video.
- ltc-gui:
  - Fix LTC source selection stuck at "Probing…" for video clips — ordering
    bug where ProbeVideo was sent before SelectRecording, which wiped the
    probe state. Also send SelectFolder during restore before auto-selecting
    a recording; warn when SelectRecording references an unknown group.
  - Fix egui widget & scrollArea ID duplication when processing multiple
    recordings in one session.
- ltc-slint:
  - Reset per-recording state (LTC decode report, conversion status,
    start-from-LTC checkbox, concat option) when selecting a different
    recording.
  - Multi-clip camera groups correctly classified as VideoClipSequence
    (was: single-file groups only).
- Engine:
  - Add SelectRecording and ClearRecordingDecodeState commands; bump decode
    generations so stale results are discarded after a recording switch.
  - Add start_timecode_from_ltc() and build_per_file_start_timecodes();
    rename trim_to_first_ltc -> set_start_from_ltc.

  - Fix progress bar hitting 100% while conversions are still ongoing.

* v0.4.1

Main features are codec-level video encoder selection with automatic hardware
fallback in the convert tab, a stream-copy mode that leaves video encoding
untouched, and audio device robustness improvements.

List of Changes:
- Convert tab:
  - Reworked video encoding to codec-level selection (av1, h264, h265, prores,
    dnxhd) with priority-ordered encoder chains — hardware encoders first,
    software fallbacks; failed encoders are skipped for the rest of the run and
    the encoder actually used is reported on completion.
  - Added VAAPI & Vulkan hardware encoder support alongside the existing
    nvenc/qsv/amf/mf/v4l2m2m candidates.
  - Run a detailed ffmpeg capability probe at startup; both GUIs now only
    offer containers/encoders that actually work, with a label showing whether
    hardware acceleration is supported per encoding.
  - Added a "Leave Video Encoding Untouched" (stream copy) mode: audio tracks
    are still extracted, the video is not re-encoded; trim points snap to the
    nearest video keyframe and the embedded start timecode is re-anchored so
    it matches the first video frame.
  - Show recording duration in the recording dropdown menu.
  - Expandable LTC decode result details for clip groups in ltc-gui.
  - Multi-file recording sequences now produce per-file output names
    (C0004-audio-track1 instead of C0003-audio-track2).
  - More robust file pattern matching using named capture groups.
  - Bug fixes: encoder fallback chain never ran on encoder init failure;
    output file preview was wrong for video clip groups and conversion encoded
    every output twice with inconsistent audio numbering; LTC decoding &
    timecode handling in multi-clip video files; convert-tab state management
    bugs in both native GUIs (track selector stored in ephemeral frame state,
    now snapshot is read-only); file name collision detection now checks
    individual file names and is a warning instead of a blocking error;
    ffmpeg probe thread exited uncleanly.
- Audio & GUI robustness/performance:
  - Refactored audio-core (playback code extracted to audio_output.rs) and
    made device handling more robust: StreamDead now triggers full recovery,
    default buffer size selection, and stream playback starts only after the
    ring buffer is prefilled.
  - Fixed egui GUI performance: a broken clap-animation check caused constant
    immediate repaints (busy loop); the GUI now sleeps when idle.
  - Added a GUI performance measurement script (perf-test/) and an
    --autostart flag for benchmark runs.
- Misc:
  - Added Windows cross-compilation instructions for the libltc dependency to
    the README.
  - Fixed clippy warnings.

* v0.4

Main features are a new much more performant slint based GUI, a new convert
tab that allows loading audio or video files with an LTC track and use that to
produce clipped versions that have the correct timecode from LTC set, ready for
import into a video editing software, and a major overhaul of the LTC decoding
performance, robustness, and reporting.

List of Changes:
- Added Slint based GUI.
- Added convert tab to all GUIs.
- Refactored the shared GUI logic into a common gui-engine crate used by both
  native GUIs (audio lifecycle, state management, CLI, decoding, conversion).
- Major LTC decoding overhaul:
  - Chunked parallel decoding of large files with progress display and
    cancellation.
  - Improved robustness against clock drift, better fallback handling, and
    fixed phase-offset and chunk-overlap bugs.
  - Added a timecode quality measure/report (confidence, gaps, glitches) with
    a verbose CLI mode and copy-report buttons in the GUIs.
  - Added a CLI flag to list all decoded timecodes in a file.
  - Made the libltc decoder (--decoder libltc) selectable in the GUIs.
  - Filter out bogus timecodes at the start of files.
- Convert tab improvements:
  - Support video files for LTC track selection and decoding.
  - LTC-based trimming to the first detected timecode frame.
  - Auto-enable split tracks & drop LTC track after LTC detection.
  - Flexible user-defined file naming patterns for grouping input files.
  - Remember last used input & output folders.
- Unified and improved ffmpeg integration: single detection shared between
  GUIs, better format/encoder capability querying and defaults, fixed mkv
  detection, audio channel mapping, and split tracks on video files.
- Changed supported sample rates to 44100 and 48000 Hz.
- Fixed a bug in the TypeScript LTC generation, with regression tests in TS & Rust.
- Added extensive unit & integration tests for audio-core and gui-engine.
- Added clippy linting to the project and fixed warnings.
- Unified default settings and colour definitions between the Rust GUIs.
- Improved the version sync script to cover all crate manifests and lock files.

* v0.3.2

Main feature is a basic CLI interface that allows for headless running of the
LTC generator.

List of Changes:
- Gracefully handle a case where the device does not support the selected
  sample rate, and the audio-core chooses a different rate. The GUI will now
  receive the actually selected rate and correctly present this information.
- Fix the infinite loop of device reinitialisation after a audio devices
  callback crashed and all attempts fail. It will now make 3 attempts and then
  stop.
- Added a basic CLI to the rust GUI that allows for headless runs, performance
  testing, and creating WAV files with a LTC timecode.

* v0.3.1

Primary focus in this release is to improve stability when working with direct
device access for specific audio devices, instead of using the system
default. Hopefully this will significantly reduce the number of crashes of
audio output for directly selected devices.

List of Changes:

- Fix the version bumping script to actually commit the files it changes.
- Fix logging window resizing to allow arbitrary window sizes.
- Improve the querying and logging of the system's audio device's supported
  features.
- Make the audio-core code more robust when directly accessing devices through
  the cpal library, instead of using default audio devices that go through the
  entire linux audio stack.
- Make audio sample rate configurable between 16MHz and 48MHz, with the default
  value being calculated depending on the device's CPU (week CPUs prefer lower
  sample rate).
- Change beep length default to 500ms and make it configurable in the GUI.
- Added a version log file.
- Added a build script that builds all supported Rust targets.
- Created a local deploy to onedrive script, and added it to gitignore.
- Use PipeWire by default, then fall back to PulseAudio, then to ALSA/JACK as
  the audio backend. Allows detection of devices such as bluetooth headsets
  that do not show in ALSA.
- Small fix to the version bumping script which had a path problem.
