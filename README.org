A SMPTE LTC timecode generator + digital clapper for multi-camera video sync,
with native desktop GUIs (ltc-gui / ltc-slint), LTC decoding, recording
conversion, and camera-card offloading. Primarily vibecoded to be good enough
for practical application.

The ltc-gui interface:
[[file:./assets/ltc-timecode-generator-ui.png]]

* System Dependencies

You need to have rust installed.

For the audio backend, you will need the pipewire & pulseaudio dev libraries:
- Debian/Ubuntu :: =sudo apt install libpipewire-0.3-dev libpulse-dev=
- Fedora/RHEL :: =sudo dnf install pipewire-devel pulseaudio-libs-devel=
- Arch Linux :: =sudo pacman -S pipewire libpulse=

* Compiling the Rust GUI

Setup:

#+begin_src bash
  cargo install cargo-zigbuild
#+end_src

Compilation:

#+begin_src bash
  cargo zigbuild --release --bin ltc-gui
  cargo zigbuild --release --bin ltc-slint
#+end_src

** Compiling the 32bit version

#+begin_src bash
  docker build --platform linux/386 -t ltc-debian11-builder -f Dockerfile.gui-build .
  docker run --rm \
         -v "$(pwd)":/app \
         -v "$(pwd)/.cargo_cache:/usr/local/cargo/registry" \
         -w /app/ltc-gui \
         ltc-debian11-builder \
         cargo zigbuild --target i686-unknown-linux-gnu.2.31 --release
#+end_src

** Cross compiling from linux to windows

Install the windows target:
#+begin_src bash
  rustup target add x86_64-pc-windows-gnu
#+end_src

Install the cross-compilation linker:
#+begin_src bash
  sudo apt update
  sudo apt install mingw-w64
#+end_src

Place the following toolchain config in =.cargo/config.toml= in the project
root (this is a developer-local setting, so not committed to git):
#+begin_src toml
  [target.x86_64-pc-windows-gnu]
  linker = "x86_64-w64-mingw32-gcc"
#+end_src

Now compile with:
#+begin_src bash
  # dev
  cargo build --target x86_64-pc-windows-gnu
  # release
  cargo build --target x86_64-pc-windows-gnu --release --bin ltc-gui
  cargo build --target x86_64-pc-windows-gnu --release --bin ltc-slint
#+end_src

* Running the Rust GUI

#+begin_src bash
  cd ltc-gui
  cargo run                    # Debug
  cargo run --release          # Release (12MB stripped)
  LIBGL_ALWAYS_SOFTWARE=1 cargo run  # Force software rendering for GPU-less testing
#+end_src
or in the project root:
#+begin_src bash
  cargo run --bin ltc-gui
  cargo run --bin ltc-slint
#+end_src


To run the rust GUI with debug output, use:
#+begin_src bash
  RUST_LOG=info cargo run --release
  # with granular settings:
  RUST_LOG=audio_core=info,ltc_gui=info cargo run --release
#+end_src

* Continuous Integration & Code Quality (SonarQube Cloud)

GitHub Actions (=.github/workflows/ci.yml=) runs the test-lint guardrail,
clippy, the Rust test suite with LCOV coverage (=cargo llvm-cov=) on every
push to =main= and every pull request, then publishes everything to
[[https://sonarcloud.io/project/overview?id=D4id4los_ltc-timecode-generator][SonarQube Cloud]] (project key
=D4id4los_ltc-timecode-generator=, organization =d4id4los=).

The Sonar scan step is skipped automatically when the =SONAR_TOKEN= repository
secret is not set, so forks run the plain CI pipeline without any setup.
Analysis configuration (sources, exclusions, report paths) lives in
=sonar-project.properties=.

Local Sonar helpers (need =jq= on the dev machine; CI runs the scanner action
directly):
#+begin_src bash
  SONAR_TOKEN=<token> scripts/sonar-gate.sh    # idempotent quality-gate setup
  SONAR_TOKEN=<token> scripts/sonar-report.sh  # deterministic report into reports/sonar/
#+end_src

* Version Bumping

The single source of truth is the =version= field under =[workspace.package]=
in the root =Cargo.toml=; all four workspace members inherit it via
=version.workspace = true=.

#+begin_src bash
  scripts/bump-version.sh patch         # 0.4.7 → 0.4.8, updates Cargo.lock, creates git commit + tag v0.4.8
  scripts/bump-version.sh minor         # 0.4.7 → 0.5.0
  scripts/bump-version.sh major         # 0.4.7 → 1.0.0
  scripts/bump-version.sh 0.6.0         # explicit version
  scripts/bump-version.sh patch --dry-run  # print the plan, apply nothing
#+end_src
The script refuses to run on a dirty working tree and verifies all four
workspace members show the new version in =Cargo.lock= before committing.


* Installing Docker

** Ubuntu

#+begin_src bash
  sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
  sudo chmod a+r /etc/apt/keyrings/docker.asc
  echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
  sudo apt update
  sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin  
#+end_src

Allow non root (i.e. you) users to run docker:
#+begin_src bash
  sudo usermod -aG docker $USER
  newgrp docker
#+end_src

* Cross Compiling Libltc on Linux for Windows builds

#+begin_src bash
# 1. Clone source code
git clone https://github.com/x42/libltc.git
cd libltc

# 2. Generate configuration files
autoreconf -vfi

# 3. Create a isolated install directory (e.g. $HOME/deps/libltc-win64)
mkdir -p $HOME/bin/libltc-win64

# 4. Configure build for Windows 64-bit MinGW
./configure \
  --host=x86_64-w64-mingw32 \
  --prefix=$HOME/bin/libltc-win64 \
  --enable-static \
  --disable-shared

# 5. Compile and install
make -j$(nproc)
make install 
#+end_src

Compile:
#+begin_src bash
BINDGEN_EXTRA_CLANG_ARGS_x86_64_pc_windows_gnu="-I$HOME/bin/libltc-win64/include" RUSTFLAGS="-L native=$HOME/bin/libltc-win64/lib" cargo build --target x86_64-pc-windows-gnu --release --bin ltc-gui
#+end_src

Make arguments automatic, edit =.cargo/config.toml=:
#+begin_src toml
[target.x86_64-pc-windows-gnu]
linker = "x86_64-w64-mingw32-gcc"
rustflags = ["-L", "native=/home/viktoria/bin/libltc-win64/lib"]

[env]
BINDGEN_EXTRA_CLANG_ARGS_x86_64_pc_windows_gnu = "-I/home/viktoria/bin/libltc-win64/include"
#+end_src
